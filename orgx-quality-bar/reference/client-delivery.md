# Client delivery: evidence before polish

Apply this to a client assignment, not to unrelated engineering or research.
The active task defines the output. Initiative context supplies purpose; it
must not silently turn a strategy brief into ten images or a complete website.

## Work from the client's reality

- Read the tenant's approved work and the actual destination website. Record
  source URLs, retrieval dates, useful excerpts, and relevant visual references.
  Never inherit OrgX's voice, industry assumptions, or design defaults.
- An empty fetch is a failed retrieval, not evidence that the site lacks content.
  Try an available alternate reader or rendered page, then existing approved
  workspace context. Reuse the retrieved source pack across tasks.
- Label an inference as an inference. A plausible audience, guessed form,
  industry norm, or suggested funnel is not a fact from the client brief.
- Preserve real links in exported work. Internal model citation tokens are not
  usable references outside that model conversation.

## Produce the requested work

| Output | Evidence required before ready for client review |
| --- | --- |
| Strategy | Specific audience and exclusions, one justified recommendation, verified current offer and destination, practical distribution and measurement, explicit assumptions that affect the choice |
| Lead list | Account and relevant public source, dated signal, fit rationale, disqualifying evidence, uncertainty and next qualification question; people/roles only when verified; no invented contact details |
| Design / PDF | Actual export and editable source; inspect every page at intended viewing size; no clipping, placeholder content, broken links, wrong brand, illegible text or unsupported claims; compare against the client's reference |
| Engineering | Reproduce the failure, change the smallest responsible boundary, demonstrate the regression test fails before and passes after, verify deployed behavior separately from local tests |
| Review delivery | One short overview linking the exact artifact versions, recommendation, what changed, and the few decisions the client actually needs to make |

A strategy document is not a rendered PDF. A source file is not a reviewed
export. A source-backed account candidate is not a qualified buyer. An internal
quality pass is not client acceptance. Keep these states separate.

## Repair without manufacturing blockers

Use existing permission and context for reversible choices. Repair retrieval,
formatting, export and attachment failures within the agreed scope and budget.
Do not ask the client to diagnose tooling, choose routine implementation details,
or reconfirm authorized work. Do not create a blocker for each failed attempt.
Escalate only a remaining dependency that genuinely needs new authority, private
information, or an unavailable capability; keep its exact failure and next step.
Never suppress such a dependency or label failed work successful to meet a
"zero blockers" target.

A failed evaluation names the defect and evidence. Fix that defect, create a new
version, and evaluate the changed work. Do not repeatedly score unchanged text,
raise the score yourself, lower the threshold, or substitute a prose description
of the missing deliverable. Read the actual applicable runtime threshold; this
skill's suggested score is not proof that the configured gate ran.

## Economical execution

Choose by cost per accepted output, not token price alone. Start with the smallest
useful complete deliverable; calibrate account fit and visual direction before
batch production. Reuse sources and approved components. Delegate only an
independent output that benefits from another specialist.

An exact model choice remains a constraint. Check the actual child run's model,
provider, task binding and budget against the request. Unknown estimates are not
zero; a cap in prose is not an enforced runtime cap. If dispatch returns an error,
read back the run before retrying to avoid duplicate paid work. Reserve budget
for verification and correction, and include research/tool/export costs.
